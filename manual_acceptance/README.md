# 人工验收记录说明

当前阶段不接 OCR、Airtest、ADB、自动点击或外部服务。

## Fribbels +0/+3 批量浏览

主窗口“导入装备 JSON”已适配本次提供的 Fribbels `items` 导出结构。导入原始文件后会自动保留 `85级 +0/+3 Epic/Heroic`，按“普通 85”处理，自动判断第一件，并显示 `当前序号 / 总数` 和中文跳过明细。使用“上一件 / 下一件”逐件查看；只有修改字段后才需要再次点击“判断”。

当前导出的独立筛选结果为：

```text
samples/real_acceptance_fribbels_20260610_plus0_plus3.json
```

共 425 件：337 件 `+0 Epic`、80 件 `+0 Heroic`、8 件 `+3 Epic`。该文件保留稳定装备实例编号，可直接导入主窗口或“真实样本管理”。原始 Fribbels 文件始终只读，不会被 GUI 或筛选过程回写。

Fribbels 数据没有本项目所需的可靠 `normal_85 / rift_85` 来源标记，因此默认使用 `normal_85`。确认属于异界的装备时，必须在主窗口改为“异界 85（仅红装）”后重新判断。

## 真实样本管理

启动 `python gui.py` 后，点击主窗口顶部的“真实样本管理”。它会打开独立窗口，不改变主窗口的分栏或尺寸。

1. 点击“导入兼容装备 JSON”，选择单件装备、`items` / `gears` / `equipment` 集合，或已保存的建议结果包。含 `acceptance_subset` 元数据的文件会作为独立验收批次导入；完成后窗口自动切换到该批次。
2. “装备来源”仅表示游戏规则中的“普通 85”或“异界 85（仅红装）”。“原始数据来源”表示最初的 Fribbels/JSON 文件；“验收批次”表示被选入的审核任务。同一装备状态可属于多个验收批次，导入子集不会覆盖原始来源或重复生成快照。
3. 强化等级可分别筛选 `+0`、`+3`、`+6`、`+9`、`+12`、`+15`，也可选择“全部未满强化”或“全部”；“验收批次”与装备来源、品质、部位、套装、审核状态和一致性条件叠加筛选。
4. 选中样本后查看已保存的工具建议、目标体系和关键 debug。详情会显示原始数据来源、所属验收批次、批次用途和覆盖标签。候选体系会分别显示当前重铸前/后有效 GS、未转换终局 GS、按转换满值的终局 GS，以及正式体系低档达标概率；另有独立的“终局 75+ 未来可期”区块，展示全部副属性官方 GS 的原生/满值转换后预期与概率。非转换候选显示“不适用”。导入时会复用当前策略生成这些结果。
5. 只填写人工判断、一致性、分歧原因和备注，点击“保存记录”。未填写一致性时，工具会根据人工判断是否等于工具建议自动填“一致”或“不一致”。

记录保存在：

```text
manual_acceptance/real_sample_records.json
manual_acceptance/real_sample_records.csv
```

JSON 是唯一事实来源；每次导入或保存人工记录后都会原子写入 JSON 并自动重建 UTF-8 BOM CSV，CSV 可直接用 Excel/WPS 查看。CSV 同时包含原始数据来源、验收批次、批次用途和批次标签；多批次归属会完整保留。旧的 `manual_test_records.csv` 仍保留为兼容模板，但不是新工具的数据源。

批量导入和保存会在后台顺序执行。窗口会显示中文阶段和进度，并暂时禁用导入/保存按钮；完成后自动恢复。保存单条人工记录时只更新当前表格行，若当前筛选不再包含该行才会移除它，不会重建整张表。

Fribbels 优先使用 `ingameId` 作为装备实例编号，缺失时使用 `id`；同一实例的不同强化状态会保存为同一样本的不同快照。`raw.code` / `code` 只是装备类型编号，不能作为实例身份。没有可靠实例编号时，仅对完全相同的装备状态去重，不会把不同强化状态推断为同一装备。

旧版 `real_sample_records.json` 会自动建立按旧 `source_file` 命名的兼容验收批次，并保留原有样本编号、快照编号、人工判断、备注和审核状态。旧版按 `code` 归并的记录仍不能安全迁移：先备份该文件，再删除记录 JSON/CSV，并从原始导出或本筛选文件重新导入。

## 导入边界

导入文件只读。若批量文件内有非法装备，会逐条报告错误，合法装备仍会保存。异界 85 紫装等现有装备校验拒绝的输入不会进入记录。

当前只适配本次实际验证过的 Fribbels `items` 结构，不会猜测解析其他第三方 JSON；其他格式仍需提供实际脱敏样本并新增独立只读适配器和回归测试。

## 记录字段

- 装备实例编号、装备类型编号、来源、品质、强化等级、套装、部位、主属性、四条副属性与强化次数
- 工具建议、目标体系、关键理由和完整 debug
- 当前重铸前/后有效 GS、未转换/满值转换终局 GS、正式体系低档达标概率、终局 75+ 未来可期 GS/概率、转换满值来源和 GS 增益
- 人工判断、一致性、分歧原因、备注、审核状态和更新时间

转换满值采用 Fribbels `Constants.modValues.reforged.greater` 的 100% 上端值，且按待转换副属性完成剩余强化后的最终强化次数计算；它不使用 `normal_85` 或 `rift_85` 普通强化跳值表。重新导入旧记录的原始装备文件时，会保留人工审核结论并补齐缺失的 GS/debug 字段。

工具建议与人工结论发生分歧时，先通过真实样本管理窗口记录，不直接调整策略。
