# 人工验收记录说明

当前阶段只做人工验收，不接 OCR、Airtest、ADB，也不做自动点击。

## 建议流程

1. 准备真实装备导出文件；优先保留 `+0 / +3`、未强化完成和需要复核的装备。
2. 先确认导出 JSON 是否符合本工具的装备字段结构；兼容时可通过“导入装备 JSON”直接导入单件或集合。非兼容导出需要单独的转换/筛选工具，当前 GUI 不会自动识别任意第三方导出格式。
3. 启动 GUI：`python gui.py`，导入兼容的装备 JSON，或在左侧手动填写一件装备字段。
4. 导入集合后使用“上一件 / 下一件”逐件查看；修改任何字段后再点击“判断”。
5. “判断”只对当前表单重新运行策略并刷新建议、下一检查点、目标体系和 debug；不会强化、保存装备、追加样本集合或记录人工结论。
6. 使用“保存装备 JSON”或“保存建议结果”保存单件复盘产物。当前 GUI 没有批量筛选未强化装备、追加集合或自动写入验收表的功能。
7. `manual_acceptance/manual_test_records.csv` 是外部 CSV 模板，不是 GUI 内置表格；可用 Excel、WPS 或任意表格工具打开后填写人工判断、一致性、分歧原因和备注。

## 记录字段

- 装备来源：`normal_85` / `rift_85`
- 品质：`Epic` / `Heroic`
- 强化等级
- 套装、部位、主属性、副属性
- 工具建议
- 人工判断
- 是否一致
- 分歧原因
- 备注

## 验收重点

- 前台建议是否足够简洁。
- debug 是否能看到策略、DP、百里分、目标分类。
- 保存结果是否能支撑复盘。
- 工具建议和人工判断分歧时，优先记录真实装备上下文，不立即改策略。

## 当前限制与推荐来源

- 若已有 Fribbels 或其他工具导出的装备文件，可先复制一份并截取未强化完成的装备；但是否能直接导入取决于其字段是否兼容本项目 JSON 结构。
- 当前项目没有“导出文件筛选器”。需要批量从第三方导出中筛选 `+0 / +3` 装备时，应单独立项实现只读转换/筛选工具，不能靠 GUI 手工录入 20-50 件。
- 自动生成的精确 DP 校准样本与真实人工验收样本用途不同。自动校准不需要手动装备；真实样本只用于验证排序和资源决策。
