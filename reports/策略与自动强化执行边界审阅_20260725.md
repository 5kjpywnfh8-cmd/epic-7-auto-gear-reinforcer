# 策略与自动强化执行边界审阅

> 修订状态：用户已批准按本审阅结论形成正式修订稿，见[策略与自动强化执行边界报告（修订稿）](策略与自动强化执行边界报告_修订稿_20260725.md)。本文件保留为审阅依据和历史记录。

## 审阅结论

报告的策略方向可以接受，但当前只能作为“未来自动强化需求草案”，不能作为执行规范或操作授权。

策略分层、Epic 早期四项联合止损、Heroic 不启用正式资源 DP、未知套装 fail closed，以及“只有明确 `continue` 才能自动进入下一段”的方向与当前 V1 基本一致。需要先修订的是执行层：当前仓库没有可用于实际点击的离散材料预算器、事前硬上限拦截器、多节点状态机或状态变化后的新鲜数据闭环。

## 与当前 V1 一致的内容

1. 三类装备的决策路由正确：
   - `normal_85 Epic`：`+0/+3` 轻量预测，适用时叠加 Epic 非速度早期止损；`+6/+9/+12` 使用精确 DP；`+15` 终局。
   - `normal_85 Heroic`：`+0/+3` 轻量预测；`+6/+9/+12` 使用基础策略，并仅在非鞋且已有速度时允许 M1 22 速救回；不启用正式资源 DP。
   - `rift_85 Epic`：`+0/+3` 轻量预测，`+6/+9/+12` 使用异界参数的精确 DP，`+15` 终局。
2. Epic 非速度早期止损范围和阈值正确：`normal_85 Epic`、85 级、非鞋、初速 `<2`、`+0/+3`；三组阈值为 `8/13`、`10/17`、`12/17`。
3. 四项条件必须同时满足才新增停止，`有效副属性 <=2` 不能单独触发停止。
4. “未知候选体系”和“未知套装”的区分正确。未知候选体系可进入默认组；未知套装必须在统一结构校验入口拒绝。
5. `rift_85` 的用户侧名称统一为“异界红装”是合理的显示约定；内部标识继续保持 `rift_85`，资源来源 `gear_source` 不得与其混为一谈。
6. “尝试至 `+15`”应理解为目标上限，不是保证到达。任一节点策略、页面、身份、资源或识别闸门失败都必须停止。

## 必须修订的内容

### 1. 前两个自动点击闸门已完成

报告“自动点击前仍需完成的闸门”第 1、2 项已经完成，不应继续列为待办：

- manifest 当前为 `5/5 ready`、缺口 `0`。
- 未知套装统一 fail closed。
- Epic `+0/+3` 三组阈值和四项联合条件已经在 JSON/Markdown 显式展开。
- 当前 manifest 核心 SHA-256 为 `050041e19c7626d20deb73e95e2894ce48a5c0e7cd685a4ae471914d7d97423b`。

它们应移动到“已完成前置条件”。`ready` 仍只表示策略契约冻结，不表示自动执行就绪。

### 2. 总预算授权会改变既有单节点授权契约

现有单件任务严格限定为“一件装备、一个复核节点、到点立即停止并重新授权”。报告提出“人工一次审核总预算后，自动尝试至 `+15`”，这是新的授权模型，不能静默继承现有任务。

未来若采用该模型，授权对象至少要绑定：

- 装备实例与当前状态哈希；
- 当前强化等级、目标上限和允许经过的节点；
- 策略 manifest 哈希；
- 允许材料、材料优先级、每种材料累计硬上限和金币累计硬上限；
- 授权有效期、撤销状态和人工中止标志。

总预算只能是整个会话的累计上限。每一段仍需派生独立分段预算并重新做策略和页面闸门，不能一次性选择到 `+15` 的全部材料。

### 3. 节点后必须刷新权威状态

装备强化后，旧 `player_data.json`、旧 `reader_result.json`、旧截图和旧建议哈希都只能作为操作前证据，不能继续证明新节点状态。batch 004 和 013 已从 `+0` 变为 `+3`，`20260722_132045` 快照对其当前属性已经陈旧。

每次实际强化后必须：

1. 保存结果截图并确认强化动画/弹窗已经结束。
2. 获取新的权威装备状态，生成同批 `player_data.json` 与 `reader_result.json`，或建立经独立验证的等价新鲜数据口径。
3. 重新唯一配对同一实例并核对当前强化等级、主副属性、资源余额和哈希。
4. 用当前 manifest 重新计算策略，旧节点建议不得沿用。

没有这一步，多节点循环会把陈旧快照误当当前状态，是自动执行的阻断项。

### 4. 当前资源模型不是自动预算器

`resource_model.py` 当前用于期望资源与体力等价研究：粉末/下级石按基础经验 `50/50` 混合，允许期望意义的分数单位，并用 Good/Great 与宠物加成计算期望值。它没有提供实际库存下的离散材料组合优化，也没有上级强化石模型。

`single_item_confirmation.py` 能在操作后校验实际材料与金币是否超过授权，但它是事后证据汇总器，不是点击前的强制拦截器。

因此报告中的“自动计算预计消耗和硬上限”尚未实现。下一预算器必须：

- 使用整数材料单位和真实界面经验/金币规则；
- 只从授权材料集合中选材，并严格遵守优先级；
- 分开输出预计值、分段硬上限和累计硬上限；
- 对上级强化石等未建模材料 fail closed；
- 证明任何材料组合、界面舍入、Good/Great 结果或确认弹窗都不能突破硬上限。

### 5. 非标准节点和强化结果必须有契约

当前策略入口只接受 `0/3/6/9/12/15`，非标准强化等级会在统一结构校验中拒绝。资源模型又显式包含 Good/Great 随机结果，因此执行规范必须先通过真实规则与测试说明一次材料提交是否可能落在 `+1/+2/+4/...`，以及发生时如何处理。

在该行为未验证前，执行器必须把“实际节点不是预期检查点”视为 `fail_closed`，不得自行向下一节点补材料或把非标准状态向下归一后继续。

### 6. 需要幂等点击和故障恢复

多节点自动化必须使用持久化状态机，而不是连续脚本点击。建议最小状态为：

`planned -> authorized -> preflight_verified -> click_intent_recorded -> click_sent -> result_observed -> node_verified -> stopped/completed`

发送点击前先落盘意图；点击后若截图、ADB、游戏或进程状态不明确，必须停在待人工恢复状态，禁止自动重发。否则超时重试可能造成第二次强化和超预算消耗。

## 两个无效属性与一次转换

现有实现已经体现“一次转换”边界：

- 早期候选只有恰好一条未命中副属性时才具有转换资格。
- 终局转换计划只选择一个候选，`gear_after_conversion` 只替换一条副属性。
- 两条无效属性不会在一次转换中同时变成两条有效属性。

但当前冻结矩阵的转换边界测试主要覆盖“单条转换可救回”和转换成本，没有一项名称和断言都直接固定“两条无效属性最多修一条”。下一策略回归维护任务应补一个小型显式测试；这属于防回归，不需要改变策略数值。

## 下一阶段建议

最先建立一个新的“自动预算与硬上限离线规划器”独立任务，只做纯 Python 离线契约和测试，不接 GUI、OCR、ADB 或模拟器点击。验收至少包括：

- 从每个标准节点到下一节点的整数材料组合；
- 普通装备与饰品材料池；
- 允许材料集合、优先级、分段/累计硬上限；
- 库存不足、未建模材料、界面预览不一致和非标准节点 fail closed；
- 预计消耗与硬上限明确分离；
- 性质测试证明任何返回计划都不越过授权上限。

该任务通过后，再建立独立的“单件多节点执行状态机”任务；最后才进行“单件、目标上限 `+15`、逐节点复核、可人工中止”的受控试点。

本审阅不构成上述任务的实现授权，也不构成任何模拟器操作或资源消耗授权。
