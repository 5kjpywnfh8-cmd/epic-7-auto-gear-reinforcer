# 纯视觉采样方案设计报告

## 结论

用户已明确要求纯视觉闭环自动强化，以降低每节点读取延迟。本报告据此把候选运行模式修订为：页面状态、目标字段、节点变化和资源显示均由连续视觉证据驱动；不调用 MuMu/Fribbels 作为运行时必经步骤。该模式可以返回“视觉上可继续”的结论，但不能证明服务端强化结果、实例连续性或真实资源扣除，必须显式标记为 `visual_only_unverified`，并在任何未知或矛盾状态下 fail-closed。此前“视觉预检 + 每节点新鲜读取”的结论保留在后文，仅作历史对照，已被本结论覆盖。

当前设计不修改正式策略、DP、评分、资源模型、GUI、OCR 门槛、Holdout、自动化规则或 MuMu/Fribbels 读取器，也不连接设备、不采集真实截图、不发送点击。

## 现有接口审计

### `visual_sampling.py`

- `PureVisualSamplingExecutor.evaluate(sample)` 是唯一业务入口，接受结构化 `Mapping` 或注入式 `ScreenshotSampler.capture()`。
- 已覆盖：目标装备精确匹配、`+0` 节点、资源计划账本、页面/候选/字段缺失和资源不足的 fail-closed、dry-run 默认、点击器零调用。
- 当前缺口：没有稳定帧或局部锚点证据；没有截图哈希、模板版本、采样窗口和超时；没有 OCR/视觉字段置信度；没有 `instance_id`、raw 或新鲜批次；没有跨节点状态；`planned` 与实际消耗没有分离；`ClickExecutor` 只是保留 seam，不能证明操作结果。

### `ocr_backpack_pair.py` / `mumu_player_data.py`

- `exact_matches()` 以同批 `player_data` 与 `reader_result.raw` 做严格字段匹配，支持 `+0` raw 主属性基值和非零节点当前主属性值。
- `validate_player_data()` 校验 schema、数量、完整性和唯一实例 ID；`validate_same_batch_raw()` 校验 raw 集合与规范化装备实例集合一致；`enriched_items()` 用 raw `op` 推导强化等级并拒绝全零或不一致状态。
- 当前接口能证明“给定双文件内部一致”，但不能从视觉采样推导新鲜双文件，也不负责页面稳定、采集顺序或资源钱包变化。

### `fresh_snapshot_contract.py`

- 已覆盖 `0 -> 3 -> 6 -> 9 -> 12 -> 15` 标准节点、同批双文件内容哈希、采集标识/时间顺序、页面明确性、`0.98` 字段置信度、唯一实例、raw 强化等级、旧文件/旧建议哈希失效和 fail-closed。
- 该模块只接受已采集的离线证据，不执行读取、点击、选材或继续指令；可作为视觉层之后的权威验证 seam。
- 后续实现需保留“允许的节点计划是标准节点的前缀或子序列但不得跳跃”的显式输入，避免把 `+0 -> +3` 任务误要求为必须采到 `+15`。

### `single_item_confirmation.py`

- 适合历史单件操作包的事后一致性核验：单次动作、节点到达、属性变化、材料/金币和立即停止。
- 其固定历史快照哈希和单件授权字段不适合作为多节点运行时入口；后续应复用检查语义，不能把历史常量直接接入新流程。

## 视觉证据协议（设计）

后续实现应把原始截图适配器与纯验证模块隔开。验证模块只接受已解析的 `VisualEvidence`，不依赖 ADB、OCR 引擎或窗口句柄。

```json
{
  "schema_version": "e7_enhance.visual_evidence/1.0",
  "operation_id": "opaque-operation-id",
  "sample_id": "opaque-sample-id",
  "captured_at": "timezone-aware ISO-8601",
  "phase": "pre_action | post_action",
  "expected_node": 0,
  "page": {
    "page_type": "enhance_equipment",
    "is_unambiguous": true,
    "target_visible": true,
    "page_signature": "sha256"
  },
  "stability": {
    "sample_count": 3,
    "stable_count": 3,
    "poll_interval_ms": 250,
    "timeout_ms": 2000,
    "frame_hashes": ["sha256", "sha256", "sha256"]
  },
  "anchors": [
    {"name": "back_arrow", "score": 0.0, "threshold": 0.0, "bright_ratio": 0.0},
    {"name": "help_icon", "score": 0.0, "threshold": 0.0, "bright_ratio": 0.0}
  ],
  "target": {
    "visible_fields": {},
    "field_confidence": {},
    "candidate_count": 1,
    "visual_fingerprint": "sha256"
  },
  "resource_preview": {
    "visible": true,
    "materials": {},
    "gold": null
  },
  "sampler": {"adapter": "opaque", "template_set": "opaque", "version": "opaque"}
}
```

约束：

- `captured_at` 必须带时区；`sample_id`、`operation_id`、模板集版本和每帧 SHA-256 必须可追溯，但报告不得写入本地绝对路径、设备地址、账号名或 raw 载荷。
- `page_signature` 只表示视觉帧，不能代替 `player_data`/`reader_result` 内容哈希。
- `candidate_count=1` 只是视觉候选唯一；最终实例 ID 仍由同批底层配对器确定。
- `resource_preview` 是页面预览，不是实际消耗。执行后必须由独立的前后资源证据或明确的读取器资源字段核对，不能用计划量直接当作扣除量。

## 分层识别与稳定等待

1. **粗路由层**：整屏模板或页面标题只用于区分大厅、控制面板、背包/英雄、强化页和未知页；动态背景、角色动画、资源数字不得成为唯一判据。
2. **局部锚点层**：在固定归一化区域检查返回箭头、帮助图标、控制面板入口、目标卡片边界等稳定元素；每个目标页至少需要两个互相独立的锚点，亮度/颜色约束与反例模板同时存在。
3. **字段层**：只在目标详情页解析套装、部位、品质、等级、节点、主属性和副属性；继续沿用 `0.98` 字段置信度和唯一候选规则。缺一字段、字段互相矛盾或候选为零/多个立即停止。
4. **稳定层**：导航或操作后每 `250 ms` 采样一次，默认要求连续 `3` 帧的页面类型、锚点状态和目标指纹一致；预检窗口建议 `2 s`，操作后窗口建议单独配置且超时即 fail-closed。具体时限需用合成时序夹具验证后才能进入实现任务。
5. **证据层**：保留原始 PNG 和逐帧哈希在本地受控证据包；公开报告只保留脱敏哈希、状态、置信度、候选数、稳定帧计数和失败原因。

整屏匹配失败但局部锚点稳定时，可以通过视觉预检；局部锚点缺失、亮度不足、网络错误弹窗、白屏或页面切换中不得放宽到单一宽区域匹配。

## 纯视觉运行闸门（当前候选口径）

| 阶段 | 必需视觉证据 | 允许动作 | 失败行为 |
| --- | --- | --- | --- |
| `bootstrap` | 已进入强化页；目标字段齐全且置信度达标；候选唯一；资源显示可见；连续稳定帧通过 | 建立一次 `visual_only_unverified` 会话账本 | `page_not_confirmed` / `target_not_unique` / `ocr_confidence_below_threshold` |
| `pre_action +0` 或 `+N` | 当前节点等于计划节点；目标视觉指纹、两个局部锚点和资源显示连续稳定；预算账本仍足够 | 仅在已有逐节点操作授权时发送一次强化操作 | `unstable_visual_state` / `node_mismatch` / `resource_preview_inconsistent` |
| `post_action` | 操作后页面重新稳定；节点文字/图标变化符合预期；目标指纹未漂移；资源显示变化与计划消耗一致 | 记录视觉结果并进入下一节点预检 | `unknown_result`；停止且禁止自动重试 |
| `next_node` | 上一节点视觉结果已确认；节点序列无跳跃；预算仍未超上限 | 继续下一次单节点操作 | `node_sequence_jump` / `visual_budget_exceeded` |
| `complete` | 达到目标节点，最终页面稳定，账本无矛盾 | 结束会话，不宣称服务端已确认 | 任何最终字段缺失均返回 `visual_completion_unverified` |

约束：

- 视觉显示的 `+3`、材料数量和金币变化只能证明“画面上显示如此”，不能替代 `raw`、实例 ID 或服务端扣款证据。
- 每个节点最多发送一次操作；点击后超时、弹窗、页面漂移、数字矛盾或无法确认时，必须停止并交给人工处理，不得盲目重试。
- 纯视觉模式必须与底层读取模式显式区分，输出 `mode=visual_only`、`verification=unverified` 和完整的截图/帧哈希证据，避免被下游误当作新鲜快照。

## 旧混合读取闸门（历史对照，已被用户要求覆盖）

| 阶段 | 视觉层作用 | 权威条件 | 失败行为 |
| --- | --- | --- | --- |
| `pre_action +0` | 确认强化页、目标可见、字段稳定、资源预览存在 | 新鲜同批双文件通过 `fresh_snapshot_contract`，实例由配对器唯一确定 | 不允许任何操作，返回 `fresh_read_required` 或 `fail_closed` |
| `pre_action +N` | 确认当前页面仍是目标装备且节点与上次验证一致 | 上一节点已验证、预算计划仍有效、当前新鲜快照未过期 | 停止，不使用旧视觉帧或旧 `current` |
| `post_action` | 等待页面稳定并观察预期节点/资源预览变化 | 新一批 `player_data`/`reader_result`、新文件哈希、raw 推导节点、实例 ID 连续、采集时间递增 | 不重发点击；标记 `unknown_result`，人工处理 |
| `next_node` | 只做下一节点页面预检 | 上一节点完整验证且计划允许该标准节点 | 未通过前不得进入下一节点 |
| `dry_run` | 可只使用结构化视觉证据给出计划预览 | 不产生任何实际操作授权 | 结果必须带 `dry_run=true` 且不含可执行点击指令 |

该表记录此前的底层读取运行口径，不再作为本轮纯视觉候选模式的必经条件。若用户后来要求恢复服务端可验证模式，必须另建任务说明，不得把两种模式的证据混用。

## 最小接口拆分建议

建议保留现有 `PureVisualSamplingExecutor` 作为 dry-run 兼容入口，后续新增以下纯视觉运行时 seam；本任务不实现：

```python
class VisualSampler(Protocol):
    def capture(self, request: SamplingRequest) -> VisualEvidence: ...

class VisualEvidenceGate:
    def evaluate(self, evidence: VisualEvidence, expected: ExpectedVisualState) -> VisualGateResult: ...

class VisualOnlyEnhanceExecutor(Protocol):
    def run_node(self, request: VisualNodeRequest) -> VisualNodeResult: ...
```

`VisualEvidenceGate` 只做页面、稳定帧、锚点、字段置信度、视觉指纹和节点/资源显示验证。`VisualOnlyEnhanceExecutor` 负责逐节点调用采样器与操作器，但输出必须携带 `mode=visual_only` 和 `verification=unverified`；不允许悄然复用旧快照或把视觉结果转换为 `FreshSnapshotPair`。

现有 `ClickExecutor` 不应被 `VisualEvidenceGate` 依赖；若未来接入点击，应将点击器放在更外层的、逐节点授权的执行器中，并要求未知结果禁止自动重试。

## Fail-closed 验证矩阵

| 编号 | 输入情形 | 预期结果 |
| --- | --- | --- |
| V1 | 动态背景变化但两个局部锚点和字段连续稳定 | 视觉预检通过，标记 `visual_only_unverified` |
| V2 | 整屏相似度高但网络错误/白屏反例锚点不满足 | `fail_closed` |
| V3 | 稳定帧少于3或超时 | `unstable_visual_state` |
| V4 | 页面正确但目标候选为0或多个 | `target_not_unique` |
| V5 | 任一字段置信度 `0.979...` 或缺失 | `ocr_confidence_below_threshold` |
| V6 | `+0` 视觉证据、目标唯一、资源显示可见且稳定 | `visual_only_unverified` 会话可建立 |
| V7 | 操作后视觉显示 `+3`，节点/指纹/资源显示均稳定 | 记录视觉结果，可进入已授权的下一节点 |
| V8 | 纯视觉会话混入双文件、跨批哈希或 raw 证据 | `mode_mismatch_rejected` |
| V9 | 视觉目标指纹漂移或候选非唯一 | `target_identity_drift` / `fail_closed` |
| V10 | `0 -> 6`、非标准节点或未知操作结果 | `node_sequence_jump` / `unknown_result` |
| V11 | 计划材料与页面预览不一致，或资源数字发生矛盾 | `resource_reconciliation_failed` |
| V12 | 点击后页面不稳定/超时 | 停止且不重发点击 |
| V13 | 相同建议文本但节点输入哈希不同 | 允许作为不同节点证据；建议哈希必须绑定节点化输入 |
| V14 | 复用旧截图、旧帧哈希或旧建议哈希 | `stale_visual_evidence_rejected` |

现有离线回归基线：`visual_sampling 6/6`、`fresh_snapshot_contract 9/9`、`mumu_player_data 7/7`、`ocr_backpack_pair 6/6`。这些测试未接入真实截图、ADB 或私人归档，不能作为运行时通过结论。

## 后续实现拆分（只作建议）

1. **视觉证据 schema 与稳定帧门**：只接收合成 `VisualEvidence`，补页面、局部锚点、字段、节点和资源数字的回归；不接设备。
2. **纯视觉单节点编排器**：把视觉预检、一次点击、操作后稳定确认和 `visual_only_unverified` 账本串起来；未知结果禁止重试。
3. **纯视觉多节点自动化任务**：在单节点离线回归和人工验收通过后，逐节点复用同一视觉证据协议；仍不得输出新鲜快照或服务端已确认结论。
4. **可选底层读取适配任务**：若未来需要服务端可验证模式，另建任务说明接入 `FreshSnapshotReader`；不得把该适配器暗含进纯视觉模式。

## 风险与未完成项

- 当前没有真实视觉采样器、局部模板版本、稳定时序数据或页面反例集，不能给出实际识别率、延迟或阈值结论。
- 当前新鲜读取器曾出现接口载荷上限和 `0 items`；纯视觉模式不依赖它，但也不能宣称绕过后仍具有服务端可验证性。
- 视觉资源数字存在动画、延迟和遮挡风险；必须用连续帧、变化方向和上限账本做 fail-closed，仍不能证明真实扣款。
- 当前契约以 `advice_hash` 唯一性阻止旧建议复用；后续需明确建议哈希是否绑定节点化输入，避免合法的相同文本建议被误判为重复证据。
- 本报告未修改任何代码，未产生真实截图、读取快照、网络请求或游戏操作；实现必须另建任务说明并重新授权。
